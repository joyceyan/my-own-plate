# CLAUDE.md — My Own Plate

AI-powered calorie and macronutrient estimation from food photos. The project fine-tunes Qwen3-VL-2B-Instruct on the Nutrition5k dataset using LoRA with full vision support via mlx-vlm, targeting an on-device iOS app with a Streamlit desktop prototype.

## Project Structure

```
app/            Streamlit desktop prototype (stub — early stage)
data/           Dataset preparation and Nutrition5k files
  prepare_nutrition5k.py       Raw N5k CSVs → nutrition5k_all.jsonl (no splitting)
  nutrition5k_all.jsonl        All valid samples, unsplit (human-readable)
  nutrition5k_train.jsonl      Training split (generated by convert_dataset.py)
  nutrition5k_validation.jsonl Validation split (generated by convert_dataset.py)
  nutrition5k_test.jsonl       Test split (generated by convert_dataset.py)
  nutrition5k_hf/              HuggingFace parquet dataset (for mlx-vlm)
  nutrition5k_baseline_data.json  Thames et al. CVPR 2021 baseline MAE values
training/       mlx-vlm LoRA fine-tuning pipeline (Apple Silicon only)
  convert_dataset.py       JSONL → train/val/test splits (parquet + JSONL)
  train.py                 LoRA fine-tuning with validation via mlx-vlm
  evaluate.py              Eval with images, MAE/MAE% metrics (--mode val|test)
  merge_and_export.py      Fuse LoRA into base weights, export to GGUF
  export.py                Placeholder — GGUF export stub (not implemented)
  output/adapters/         LoRA adapter checkpoints
  eval_results/            Per-sample CSV and summary JSON from evaluation
  notes.md                 Experiment log and ideas queue
  results.tsv              Structured results for all experiments
ios/            iOS app placeholder (Xcode project not yet initialized)
program.md      Autonomous experiment loop spec (point Claude Code here to run)
```

## Tech Stack

- **Training**: mlx-vlm (Apple Silicon native, full vision-language pipeline)
- **Base model**: `mlx-community/Qwen3-VL-2B-Instruct-bf16` (2B param VLM)
- **Fine-tuning**: LoRA on language model attention projections (q/k/v/o_proj), rank 16, alpha 32
- **Inference**: mlx-vlm generate (passes images through the vision tower)
- **Export**: GGUF via llama.cpp (optional)
- **Desktop prototype**: Streamlit + llama-cpp-python
- **Dataset**: Nutrition5k (Thames et al., CVPR 2021) — 80/10/10 train/val/test split
- **Target deployment**: iOS (Swift/SwiftUI, planned)

## Commands

### Data Preparation
```bash
# Step 1: Raw CSVs → single JSONL (requires Nutrition5k at ~/src/Nutrition5k/)
cd data && python prepare_nutrition5k.py

# Step 2: Split into train/val/test and convert to HuggingFace parquet
cd ../training && python convert_dataset.py
```

### Training (Apple Silicon only)
```bash
cd training
pip install -r requirements_mac.txt
python train.py --train-data ~/src/my-own-plate/data/nutrition5k_hf
```
Default hyperparams are tuned for M2 Pro 32GB. Validation loss is computed every 200 steps. See `training/README.md` for full flag list.

### Evaluation
```bash
cd training
# Development: evaluate on validation set (default)
python evaluate.py --adapter-path ./output/adapters

# Final reporting: evaluate on held-out test set
python evaluate.py --adapter-path ./output/adapters --mode test
```
Evaluates fine-tuned model (base + LoRA adapter) with images, side-by-side with the base model and N5k baselines. Use `--no-base` for faster runs.

### Merge & Export
```bash
cd training
python merge_and_export.py --adapter-path ./output/adapters --output-dir ./output
```
GGUF conversion requires a local llama.cpp clone. Set `LLAMA_CPP_DIR` or `--llama-cpp-dir`.

### Streamlit App
```bash
cd app
pip install -r requirements.txt
streamlit run app.py
```

## Important Constraints

### mlx-vlm vs mlx-lm
**mlx-vlm is required for vision-language fine-tuning.** mlx-lm strips the vision tower from VL models (its `sanitize()` method discards visual weights), making training text-only — the model never sees images. An earlier version of this project used mlx-lm and produced a model that collapsed to constant output because it was blind. mlx-vlm keeps the full VL pipeline.

### Metal GPU Timeout
On Apple Silicon laptops, long GPU commands trigger macOS "Impacting Interactivity" kills. The training script mitigates this by:
1. Disabling `mx.compile` by default
2. Capping Metal memory to 50% of GPU VRAM
3. Using gradient checkpointing and batch size 1

Do not increase batch size or enable `mx.compile` without ample free memory. Close browsers/Docker/Slack before training — aim for <16 GB system RAM in use.

### macOS Sleep Prevention
**Always wrap long-running commands (training, evaluation) with `caffeinate -i -s`** to prevent macOS from sleeping and suspending the process. Closing the laptop lid without `caffeinate` will pause training entirely.

### Data Pipeline
- `prepare_nutrition5k.py` reads raw N5k CSVs → single `nutrition5k_all.jsonl` (clean, normalize, filter — no splitting).
- `convert_dataset.py` reads `nutrition5k_all.jsonl` → 80/10/10 train/val/test split → HuggingFace parquet + per-split JSONL files. All split logic lives here.
- **Splitting is done at the dish ID level**, not the image level. All images for a given dish land in the same split to prevent data leakage (N5k has multiple camera angles per dish).
- JSONL format: `image_path`, `prompt`, `completion` (JSON string with `ingredients`, `calories`, `protein`, `fat`, `carbs`).
- HuggingFace parquet columns: `image` (PIL), `question`, `answer`.
- Split ratios and seed are configurable via CLI args on `convert_dataset.py`.

### Evaluation Modes
- `--mode val` (default): Use during development, checkpoint selection, hyperparameter tuning. Runs on validation split.
- `--mode test`: Use once for final reporting. Runs on held-out test split.

### requirements.txt Structure
- `training/requirements_mac.txt` — the actual deps: mlx-vlm, Pillow, numpy, datasets, torchvision
- `training/requirements.txt` — leftover PyTorch/HF deps from an earlier approach (not used by MLX pipeline)

## Code Conventions

- Pure Python scripts with `argparse` CLIs — no framework, no config files.
- Module-level docstrings describe purpose and known limitations.
- Section separators use `# ---...---` comment blocks.
- All scripts use `if __name__ == "__main__": main()` pattern.
- Paths default to `~/src/...` conventions — always expanduser before use.
- JSON output for model completions; regex fallback parsing in evaluate.py.

## Do's and Don'ts

- **Do** use `mlx-vlm` (not mlx-lm) for all model loading, training, and inference.
- **Do** run `convert_dataset.py` before training (creates splits + HuggingFace format).
- **Do** use `--mode val` during development; reserve `--mode test` for final reporting.
- **Do** keep `--batch-size 1` and `--grad-checkpoint` for laptop training.
- **Do** use `training/requirements_mac.txt` (not `training/requirements.txt`) for MLX training.
- **Don't** commit large files under `training/output/` or `data/nutrition5k_hf/`.
- **Don't** use mlx-lm for VL models — it strips the vision tower silently.
- **Don't** enable `mx.compile` on shared/laptop systems without testing for GPU timeout first.
- **Don't** repeatedly evaluate on the test set — use validation for iteration.

## Experiment Loop

To run the autonomous fine-tuning optimization loop, read `program.md` and follow its instructions. Progress is tracked in `training/notes.md` (experiment log + ideas queue) and `training/results.tsv` (structured metrics). Success criteria: average MAE% across calories/protein/fat/carbs must improve, and no individual nutrient may degrade by more than 5 percentage points.
